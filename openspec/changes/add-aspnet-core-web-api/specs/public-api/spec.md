# Spec Delta

## Purpose

Exposes read-only HTTP endpoints for API health, sample weather data, and basic application information, with documentation available only in Development.

## ADDED Requirements

### Requirement: Health status

The API SHALL expose `GET /api/health`. A successful response SHALL use HTTP 200 and `application/json`, and SHALL report that the API is healthy. The endpoint SHALL NOT require authentication and SHALL succeed when no database is configured.

#### Scenario: Client checks health

- **WHEN** a client sends `GET /api/health`
- **THEN** the response status is 200
- **AND** the JSON body uses the shared success shape with `"status": "ok"`
- **AND** `data.healthy` is `true`

### Requirement: Sample weather forecast

The API SHALL expose `GET /api/weatherforecast`. A successful response SHALL use HTTP 200 and `application/json`, and SHALL return at least one sample forecast. Each forecast SHALL include a date, a numeric temperature, and a short text summary. The values MAY be generated by the API and SHALL NOT depend on an external weather service or a database. The endpoint SHALL NOT require authentication.

#### Scenario: Client requests the sample forecast

- **WHEN** a client sends `GET /api/weatherforecast`
- **THEN** the response status is 200
- **AND** the JSON body uses the shared success shape with `"status": "ok"`
- **AND** `data` is a non-empty array
- **AND** each entry includes a date, a numeric temperature, and a text summary

### Requirement: Application information

The API SHALL expose `GET /api/info`. A successful response SHALL use HTTP 200 and `application/json`, and SHALL identify this API by name and report the current hosting environment. The response SHALL NOT include secrets, credentials, or connection strings. The endpoint SHALL NOT require authentication.

#### Scenario: Client requests application information

- **WHEN** a client sends `GET /api/info`
- **THEN** the response status is 200
- **AND** the JSON body uses the shared success shape with `"status": "ok"`
- **AND** `data.name` identifies the Xplore API
- **AND** `data.environment` names the current hosting environment
- **AND** the body contains no secrets or credentials

### Requirement: Shared success response

`GET /api/health`, `GET /api/weatherforecast`, and `GET /api/info` SHALL use the same JSON success shape: an object with `status` equal to `"ok"` and a `data` property holding the endpoint payload.

#### Scenario: Success responses match

- **WHEN** a client calls each of the three endpoints successfully
- **THEN** every response is JSON with top-level `status` and `data` properties
- **AND** every `status` value is `"ok"`

### Requirement: Development-only API documentation

When the API runs in the Development environment, it SHALL serve an interactive OpenAPI (Swagger) UI at `/swagger`. When the API runs in any other environment, that UI SHALL NOT be available.

#### Scenario: Documentation is available in Development

- **WHEN** the API is running in Development
- **AND** a client requests `GET /swagger`
- **THEN** the interactive API documentation is returned

#### Scenario: Documentation is hidden outside Development

- **WHEN** the API is running outside Development
- **AND** a client requests `GET /swagger`
- **THEN** the interactive API documentation is not served
